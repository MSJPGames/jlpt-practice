N1 聴解の音声を作る（全部作り直します）

【今回のこと】
  N1の聴解を本試験の形にそろえました。台本が変わったので、
  297本すべてを作り直します。30分ほどかかります。

  ・概要理解・即時応答・統合理解の163問に「選択肢の読み上げ」を足しました
    （本試験では、この3つの大問の選択肢は問題用紙に印刷されず、音声で読まれます）
  ・課題理解・ポイント理解の87問で、会話の前に設問を読むようにしました
  ・場面か設問が音声に入っていなかった22問に、ナレーターを足しました
  ・場面のあと／設問の前／選択肢と選択肢の間に「間（ま）」が入るようになりました
  ・音声の特徴（もんだい6）は今までどおりです（聞き分けの練習なので読み上げません）

【要るもの】
  Python 3 と edge-tts（.bat が自動で入れます）
  同じフォルダに次の3つ：
    make_n1_listening_audio.py     ← 新しいもの
    n1_listening_manifest.json     ← 新しいもの（297本ぶん）
    file_to_daimon.json            ← 新しいもの

【やりかた】
  1) この3つを「JLPT PRACTICE」フォルダに上書きする
  2) make_n1_listening_audio.bat をダブルクリック
  3) 待つ（297本で30分ほど）
  4) audio フォルダの n1_q*.mp3 を、HTMLと同じ場所に置いてGitHubへ

  途中で止めても大丈夫です。もう一度実行すれば、できていないぶんだけ作ります。

【なぜ全部作り直すのか】
  これまでの無音は、mp3の中に「ID3タグ」が混ざる作り方でした。
  そのため297本のうち196本が、フレームの切れ目のそろわないmp3になっていました。
  今回から、24kHz・48kbps の無音フレーム（144バイト＝0.024秒）を並べる作りにします。
  この作りなら、**ファイルの大きさが必ず144の倍数**になるので、
  壊れていないことを機械で確かめられます。
  N2・N3の音声はすでにこの作りで、すべて144の倍数になっています。

【確かめること】
  ・ログの最後が failed 0 になっていること
  ・audio フォルダの n1_q*.mp3 が 297本あること
  ・どのファイルも 144バイトの倍数であること

【間（ま）の長さについて】
  N1の公式CDはまだ実測していないので、N2の実測値をそのまま使っています。
  N1の公式CDが手に入ったら測り直します（n1_audio_timing.json に書いてあります）。
